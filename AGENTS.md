# PGIMER CP/047 Mission Control

## Non-negotiable product objective

This repository is a personal exam-preparation system for ONE target only:

**PGIMER Satellite Centre, Sangrur — Computer Programmer, Post Code CP/047, Group B.**

Do not broaden the product into generic Computer Science preparation, other government exams, interview preparation, coding interviews, or unrelated competitive exams.

The application must serve as both:
1. a **PGIMER-targeted MCQ practice platform**, and
2. a **study/reference system** where questions teach the underlying concept after answering.

## Official target exam facts

Use the official PGIMER recruitment notification / recruitment rules already supplied in the project context as authoritative.

- Post: Computer Programmer, CP/047, Group B, PGI Satellite Centre, Sangrur.
- Vacancy: 1 UR.
- CBT: 100 single-answer MCQs, 100 minutes, 100 marks, English.
- Marking: +1 correct, -0.25 wrong, 0 unattempted.
- No interview for this Group B post.
- PGIMER does NOT publish a guaranteed chapter-by-chapter CP/047 syllabus. Its guidance ties the CBT to the prescribed educational qualification/professional course and may include topics studied/practiced during that course.
- Never claim a topic is guaranteed unless an official PGIMER source supports it.
- Essential qualification/experience rules are eligibility rules, not automatic evidence of exam weightage.
- Formal training in programming/system design/analysis and programming-language knowledge are desirable qualifications; do not mislabel them as mandatory exam subjects.

## Topic map

### C
Data types, variables, operators, precedence, expressions, control flow, functions, arrays, strings, pointers, pointer arithmetic, structures/unions, dynamic memory, recursion, storage classes, scope/lifetime, file handling, preprocessor, output tracing and code behavior.

### Data Structures
Arrays, linked lists, stacks, queues, deques, trees, BST, AVL, heaps, hashing, graphs, BFS, DFS, traversals, operations and complexity.

### Algorithms
Big-O / Big-Theta / Big-Omega, best/average/worst case, searching, sorting, stability, divide-and-conquer, greedy, dynamic programming basics, recursion complexity, graph algorithms.

### DBMS / SQL
Relational model, ER model, keys, functional dependencies, normalization 1NF/2NF/3NF/BCNF, relational algebra, SELECT/WHERE/ORDER BY/GROUP BY/HAVING, joins, subqueries, aggregates, views, indexes, transactions, ACID, concurrency, locks, integrity constraints, recovery, MySQL/PostgreSQL basics.

### Operating Systems
Processes, threads, PCB, process states, scheduling, FCFS/SJF/RR/Priority, scheduling calculations, synchronization, critical section, race conditions, semaphores/mutex, deadlocks, paging, segmentation, virtual memory, page replacement, file systems, system calls, Unix/Linux basics.

### Networks
OSI, TCP/IP, TCP vs UDP, IPv4/IPv6, addressing/subnetting, ARP, ICMP, DNS, DHCP, HTTP/HTTPS, FTP, SMTP/POP/IMAP, ports, routing, switching, network devices, flow/error/congestion concepts, basic network security.

### C++ / OOP
Classes/objects, encapsulation, abstraction, inheritance, polymorphism, constructors/destructors, overloading/overriding, virtual functions, access control, templates/STL only to the level supported by comparable Programmer evidence, exceptions.

### Java
Classes/objects, inheritance, interfaces, abstract classes, exceptions, collections, threads/multithreading basics, JVM/JIT concepts, I/O basics, language behavior. Avoid advanced frameworks.

### COA / Digital Logic
CPU, ALU, control unit, registers, instruction cycle, memory hierarchy, cache, addressing modes, I/O, interrupts, buses, number systems, complements, Boolean algebra, logic gates, truth tables, K-map/simplification, flip-flops, counters, combinational/sequential circuits, basic pipelining.

### Software Engineering / System Analysis
SDLC, waterfall/iterative/agile basics, requirements, SRS, feasibility, design, testing, verification/validation, unit/integration/system testing, maintenance, coupling/cohesion, DFD, flowcharts, data dictionary, structured analysis/design, modularity, implementation.

### Linux / Troubleshooting
Files/directories, permissions, processes, users/groups, shell commands, networking commands, Ubuntu/Linux basics, system troubleshooting.

### Web / Internet / PHP
HTTP request/response, client/server, HTML/CSS/JS fundamentals, forms, cookies/sessions, server-side basics, PHP basics, REST/internet fundamentals, web-security basics.

### Discrete Mathematics
Propositions, logical operators, truth tables, implication/equivalence, sets, relations, functions, partial orders, graphs, basic counting.

### Security
Authentication/authorization, hashing, symmetric/asymmetric encryption, digital signatures, malware, common attacks, HTTPS/TLS, access control.

### Compiler / System Software
Compiler/interpreter/assembler, linker/loader, lexical/syntax analysis, code generation, macro processor, storage allocation.

### Storage / RAID
File organization, indexing, B/B+ trees, RAID basics, storage, backup/recovery.

## Question-quality contract

Every active question must have:
- exactly 4 options,
- exactly one correct answer,
- subject + topic,
- realistic difficulty,
- teaching explanation,
- source/provenance metadata.

Allowed provenance values:
- PYQ
- PYQ-derived
- source-grounded
- original

### PYQ reuse

Do not bulk-copy or expose copyrighted question-paper text merely because a PDF was supplied.
Use source papers to identify recurring concepts and MCQ patterns, then create original questions that test those concepts. Retain source metadata. Do not claim an original question is a verbatim PYQ.

## AI generation: PGIMER mode

Generate questions that reflect the researched Programmer-exam style rather than generic trivia.

Prioritize:
- conceptual questions,
- code/output tracing,
- SQL/result reasoning,
- OS scheduling/calculation,
- complexity comparison,
- normalization/transaction reasoning,
- protocol/architecture identification,
- data-structure behavior.

Every generation batch:
- exactly N single-answer MCQs,
- exactly 4 plausible options each,
- exactly one correct option,
- English only,
- grounded in the supplied source when source-grounded mode is selected,
- no invented source facts,
- explanation must teach why the answer is correct,
- never auto-activate generated content.

Do not create a bank dominated by easy definitions. Target roughly 25–35% straightforward recall, 35–45% application/reasoning, and 20–30% tricky/code/calculation/output, adjusting to evidence from the source papers.
